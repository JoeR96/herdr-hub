# Evidence pages for worktrees — design

Date: 2026-10-12
Status: draft, awaiting review

## Goal

When Claude finishes work in a git worktree and has proof that it works (screenshots, GIFs, videos, test output, logs, diffs, notes), that proof ends up on one Claude Artifact page for the worktree. herdr shows which worktrees have a page and opens it from the hub menu.

Success looks like this: Joe opens the hub menu on a worktree, picks "Open evidence", and sees everything Claude used to show the work is done, newest first, without asking for it.

## Decisions already made

- **Trigger:** a hook nudges and Claude decides. Claude publishes only when it has saved evidence that isn't on the page yet. Sessions with no evidence are never nagged.
- **Scope:** one living page per worktree. It's republished to the same URL and each publish adds a new "round" on top.
- **Sidebar marker:** in v1.

## Overview

| Piece | Lives in | Job |
|---|---|---|
| `.evidence/` folder | each worktree | the evidence files, `evidence.json` (item list), `artifact.json` (page link) |
| `evidence` CLI | `~/.claude/skills/evidence/evidence.ts` | `add`, `build`, `published`, `status` |
| `evidence` skill | `~/.claude/skills/evidence/SKILL.md` | tells Claude what to capture and how to publish |
| SessionStart hook | `~/.claude/hooks/evidence-session-start.ts` | in a worktree, reminds Claude to save proof |
| Stop hook | `~/.claude/hooks/evidence-stop.ts` | blocks one stop when there's unpublished evidence |
| herdr-hub changes | this repo | "Open evidence" menu item and sidebar marker |

Everything is Node 24 TypeScript with no dependencies, run straight with `node` like herdr-hub, so the tools work cross-platform and use the same test setup (`node --test`).

## 1. The `.evidence/` folder

Created by the first `evidence add`. Nothing creates it up front.

```
<worktree>/.evidence/
  evidence.json      # item list and round counter
  artifact.json      # { url, publishedAt, publishedRound } (written after the first publish)
  files/             # copied evidence files, named <n>-<slug>.<ext>
  site/index.html    # generated page (output of `evidence build`)
```

`evidence.json`:

```json
{
  "version": 1,
  "round": 2,
  "items": [
    { "id": 7, "round": 2, "kind": "screenshot", "file": "files/7-login-page.png",
      "caption": "Login page after the fix", "addedAt": "2026-10-12T14:03:11Z" }
  ]
}
```

- `kind` is one of `screenshot`, `gif`, `video`, `test-output`, `log`, `diff`, `note`.
- `round` starts at 1. Items always join the current round. `evidence published` closes the round (sets `publishedRound = round`) and opens the next one.
- On first creation, `.evidence/` is added to the repo's shared exclude file (`$(git rev-parse --git-common-dir)/info/exclude`), once and only if it isn't there already, so it never gets committed in any worktree.
- The folder stays outside the repo history. When herdr-hub cleanup deletes a worktree, the local evidence goes with it, but the published page stays online.

## 2. The `evidence` CLI

Run as `node ~/.claude/skills/evidence/evidence.ts <command>` from anywhere inside the worktree. It finds the worktree root with `git rev-parse --show-toplevel`.

- `add <file|-> --kind <kind> --caption "<text>"`: copies the file into `files/`, or reads stdin when given `-`, and appends an item. If `--kind` is left out, it's guessed from the extension (`.png/.jpg/.webp` → screenshot, `.gif` → gif, `.mp4/.webm` → video, `.diff/.patch` → diff, otherwise log). Text over 200 KB keeps the last 200 KB with a "truncated" note. Video over 15 MB is refused with a clear message (the Artifact per-file limit).
- `build`: writes `site/index.html` and prints JSON to stdout: `{ "page": "<abs path>", "files": { "files/7-login-page.png": "<abs path>", ... }, "url": "<existing url or null>" }`. Claude passes that JSON straight to the Artifact tool.
- `published <url>`: writes `artifact.json` with the url, `publishedAt` and `publishedRound`, then opens the next round.
- `status`: prints `{ worktree, unpublished: <count>, url }`. The Stop hook uses the same logic.

### The page

Generated by a template in the CLI, so every page looks the same. It follows the Artifact page rules: a short `<title>` (`Evidence · <branch>`), colour tokens on `:root` with dark-mode overrides, an explicit `body` background, works at phone width, no external scripts.

- **Header:** repo name, branch, worktree path, last commit (short sha and subject), last updated time.
- **Rounds:** newest first, each headed "Round N · <time>". Within a round, items appear in the order they were added:
  - screenshot/gif: `<img>`, click to open full size
  - video: `<video controls>`
  - test-output/log/diff: collapsible `<details>` with `<pre>`, open by default for test output, diff lines coloured
  - note: paragraph text
- Images and videos are referenced as supporting files (`files/...`), not inlined as data URIs, to keep the page small.

## 3. The `evidence` skill

`SKILL.md` covers:

- **What counts as evidence:** anything you used to convince yourself the work is done, such as screenshots of the running app, GIFs of a flow, test or build output, a before/after pair, or a diff summary. Save it at the moment you check it, not afterwards.
- **How to save it:** examples of `evidence add` for a file, for piped output (`npm test 2>&1 | node … add - --kind test-output --caption "…"`), and for a browser screenshot or GIF saved to disk first.
- **How to publish:**
  1. Run `evidence build` and read its JSON.
  2. If `url` is null, call Artifact `publish` with `file_path` = page, `files` = the map, and `icon: "check"`.
  3. If `url` is set, first call Artifact `read` on it (needed when this conversation hasn't published it), then `publish` with `url`, `file_path` and `files`.
  4. Run `evidence published <url>` with the URL the Artifact result returned.
  5. Give the user the link in one line.
- **Don't:** publish evidence that contains secrets, tokens or personal data; pad the page with things that prove nothing.

## 4. The hooks

Both are registered in `~/.claude/settings.json` alongside the existing herdr SessionStart hook, never replacing it:

```json
"SessionStart": [{ "hooks": [{ "type": "command", "command": "node C:/Users/Administrator/.claude/hooks/evidence-session-start.ts" }] }],
"Stop":         [{ "hooks": [{ "type": "command", "command": "node C:/Users/Administrator/.claude/hooks/evidence-stop.ts" }] }]
```

Both read the hook JSON from stdin, use its `cwd`, and **exit 0 with no output on any error** (not a git repo, git missing, bad JSON). A broken evidence tool must never block or slow a Claude session.

"Is a linked worktree" means `git rev-parse --git-dir` and `--git-common-dir` resolve to different paths. Main checkouts are left alone.

**SessionStart.** In a linked worktree, prints:

```json
{ "hookSpecificOutput": { "hookEventName": "SessionStart",
  "additionalContext": "This session is in git worktree <path> (branch <b>). When you verify your work - screenshots, test runs, before/after - save the proof with the evidence skill (`evidence add`). It is published as an evidence page for this worktree." } }
```

**Stop.**
- If `stop_hook_active` is true, the hook exits silently. This guarantees at most one block per turn.
- If the cwd isn't a linked worktree, or `.evidence/evidence.json` doesn't exist, it exits silently.
- If there are items with `round > publishedRound` (or no `artifact.json` yet), it prints `{ "decision": "block", "reason": "This worktree has N unpublished evidence item(s). Publish them with the evidence skill (build, Artifact publish, evidence published), then finish." }`.
- Cost on a normal turn: one `git rev-parse` and one small file read.

`SubagentStop` is not hooked. Subagents can `evidence add`, and the parent publishes.

## 5. herdr-hub changes

A new pure function `readEvidence(worktreePath): { url: string; publishedAt: string; unpublished: number } | null` in `src/model/evidence.ts`. File reading stays in `src/io`, following the existing model/io split. It returns null when `artifact.json` is missing or invalid.

- **Menu** (`src/ui/menu-items.ts`, `src/ui/menu.ts`): `MenuInfo` gets `evidenceUrl: string | null`. When set on a worktree, the item `{ id: "open-evidence", section: "This space", label: "Open evidence page" }` goes straight after "Open PR". The handler calls the existing `openUrl`, which already only allows http(s).
- **Sidebar** (`src/model/lines.ts`): `SpaceView` gets `evidence: { unpublished: number } | null`. For worktrees the branch line gets a word suffix rather than a small glyph, so it's readable at a glance:
  - `feature/x ✓ ⇡2 · evidence` when the page is up to date
  - `feature/x ✓ ⇡2 · evidence +3` when 3 items are waiting to be published
  - no suffix when the worktree has no page and no evidence
- The daemon reads evidence when it builds each worktree's view, on the same refresh cycle as git status. No new watcher.
- README: one short section on evidence pages and how they link to worktrees.

## Error handling

- CLI: a clear one-line error and non-zero exit for bad input (missing file, unknown kind, oversize video, not inside a git repo). A corrupt `evidence.json` is reported, never overwritten.
- Hooks: always fail open (silent exit 0).
- Hub: a missing or bad `artifact.json` means no menu item and no marker, never a crash.
- Artifact publish failure: the skill tells Claude to report it to the user and **not** run `evidence published`, so the Stop hook nudges again next turn. Because of the `stop_hook_active` guard, this can't loop within a single turn.

## Testing

- `evidence.ts`: `node --test` with temp git repos and worktrees covering add (file, stdin, kind guessing, truncation, video limit), exclude-file write being idempotent, round logic, build output JSON and HTML containing every item, `published`, and corrupt-file handling.
- Hooks: tests feeding stdin JSON for each case (main checkout, worktree with no evidence, unpublished, published, `stop_hook_active`, garbage input).
- herdr-hub: unit tests for `readEvidence`, `menuItems` with and without `evidenceUrl`, and `buildLines` suffixes.
- End to end, by hand: a throwaway worktree, take a screenshot, finish, check the Stop hook blocks once, the page publishes, the sidebar shows `· evidence`, and the menu opens the page. Republish adds round 2 to the same URL.

## Out of scope

- Attaching the evidence link to the GitHub PR automatically (easy follow-up: `gh pr comment`).
- Collecting evidence from screenshots Claude never saved to disk.
- Evidence for main checkouts or non-git folders.
